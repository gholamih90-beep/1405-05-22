## نکته مهم

وزن بارگیری شناورها در فایل Excel به‌صورت یک فیلد عددی در شیت شناورها وجود ندارد؛ بنابراین برنامه آن را حدس نمی‌زند. گزارش‌ها «وزن تخصیص‌یافته» را از Allocation محاسبه می‌کنند.

## اجرا

پوشه `hg-erp` را روی سیستم مقصد کپی کنید و `index.html` را با مرورگر محلی باز کنید.

اگر مرورگر اجازه IndexedDB در `file://` نداد، پروژه را با یک وب‌سرور محلی ساده اجرا کنید. اینترنت لازم نیست.

## داده واقعی و DEMO

داده‌های DEMO اولیه پروژه حذف شده‌اند. در اولین اجرا، داده واقعی Excel وارد IndexedDB می‌شود.

در صورت استفاده از نسخه قبلی همین پروژه در همان مرورگر، برنامه در صورت تشخیص داده‌های DEMO آن‌ها را با داده واقعی Excel جایگزین می‌کند.

## پشتیبان

از بخش «پشتیبان‌گیری» می‌توان کل پایگاه داده IndexedDB را به JSON خروجی گرفت و بعداً بازیابی کرد.


## نسخه v2 — اصلاحات اجرایی

این نسخه بر پایه همان داده واقعی Excel ساخته شده و معماری قبلی را تغییر نمی‌دهد.

اصلاحات اصلی:
- جلوگیری از تقسیم قبضی که قبلاً تخصیص مستقیم دارد.
- نمایش دلیل غیرفعال بودن تقسیم قبل از ورود اطلاعات.
- نمایش «شماره اظهار» واقعی از `koutaj_no` فایل منبع؛ شناسه `declaration_no` صرفاً داخلی است.
- افزودن «ثبت تخصیص جدید» مستقل.
- جدا شدن مفهوم قبض و اظهار در ثبت عملیات شناور.
- وزن عملیات شناور به‌صورت محاسباتی از مجموع تخصیص‌های اظهارهای همان عملیات محاسبه می‌شود و فیلد وزن دستی ندارد.
- افزودن حذف کنترل‌شده قبض؛ قبض دارای فرزند/تخصیص قابل حذف نیست.
- جلوگیری از حذف فرزندِ والد تقسیم‌شده که باعث برهم خوردن تراز شجره می‌شود.
- تخصیص‌های ابطال‌شده در موجودی محاسبه نمی‌شوند.
- ایجاد فرزند جدید خارج از فرآیند تقسیم برای والد دارای فرزند یا تخصیص مستقیم مسدود است.

این نسخه هنوز «تطبیق کامل همه فرم‌های Excel با تک‌تک ستون‌های ورودی» را به‌عنوان یک پروژه مستقل تکمیل نکرده؛ این بخش باید در فاز بعدی با Data Dictionary واقعی ستون‌های Excel انجام شود.
